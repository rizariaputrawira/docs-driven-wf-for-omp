# OMP compatibility and upgrade checks

This suite is passive Markdown plus the existing custom-agent schema. It adds no runtime import, hook, router, service, package, model profile, configuration key or approval mechanism. Skill text cannot grant permissions or provide OS containment. The maintained owner is `config/skills-agents/engineering-docs/`; staging receipts describe an older historical package, not this replacement suite.

## Three independent layers

After an OMP upgrade, record the exact installed version and separately assess:

1. **Payload and deployment:** frontmatter names/descriptions, package-local and conditional cross-skill references, pinned SOURCES and full applicable notices, explicit inventory completeness, and installer/doctor behavior in disposable homes. Compare protected paths/bytes/modes/symlinks with the genuine pre-write receipt. No historical frozen suite receipt is promoted to current acceptance.
2. **Installed public interfaces:** run `omp --version` and `omp --help` from a disposable workspace/state before using flags. Check actual discovery, enabled native names, `skill://` reference loading, custom-agent parsing/selection and current task/schema interface. Published moving `main` documentation is reference evidence only. A metadata parse is not discovery or dispatch proof.
3. **Tool-enabled behavior:** use fresh authenticated actors, the actual source-loaded skills and relevant branches, equivalent private fixtures and observable reads/searches/results/mutations. Record actor/model/thinking/fallback identity, source basis, actual tools, terminal output and before/after metadata. Independently inspect behavior rather than accepting the author's pass assertion. Source-loaded assessment is not native registration, Plan Mode enforcement, sandboxing or full-suite proof.

The cutover session observed public `omp/18.5.0` version/help. Its help includes `--config`, `--model`, `--thinking`, `--profile`, `--no-skills`, `--skills`, `--print`, `--mode`, `--no-session` and file-prefixed `@` input. This observation alone does not validate authenticated generation, custom-agent provenance, native URI resolution or unknown future releases. Consult the root README for the completed cutover evidence and limits.

## Safe unavailable and disabled behavior

Routing applies only to an available, enabled suite and matching current request. Deliberate disablement/filtering wins. Missing suite assets do not stop ordinary native OMP work or trigger setup or automatic file reads. Continue higher-priority permissions and ordinary context checks; only an explicitly requested unavailable suite-specific proof is blocked.

If convenience invocation/URI support alone is unavailable and the enabled suite is explicitly requested, read the known canonical SKILL file and resolve its references against that explicitly authorized directory. Mark native discovery unverified. This fallback must not reactivate disabled/filtered assets. A renewed explicit authorization to load a known file is a separate request, not automatic fallback.

On the observed version, the user-invoked escape hatch is `omp --no-skills`. It disables skill discovery/loading, not AGENTS guidance, custom agents, runtime tools, approval state or model state. Conditional routing honors it and does not automatically file-load the suite. If a later installed help lacks this flag, stop that command and consult its public interface, never guess replacements.

## Security role acceptance

Before accepting suite security results, establish effective execution-time definition provenance: intended managed source/procedure/schema, dispatched source path/content basis, effective permitted read-only operations and no child-spawn authority. Actual worker identity/model and a matching output shape alone cannot establish this. Inspect higher-precedence project overrides, invalid/recovered files and bundled same-named substitutes where public evidence permits. A malformed or overridden definition leaves managed-suite confirmation incomplete even when a same-named agent runs. A task-supplied schema cannot supply missing definition provenance.

Use native strict schema mode where supported with the intended effective schema, then independently validate lifecycle semantics and complete terminal phase arrays in [security](security.md). Missing/changed task interfaces, unavailable independent source readers, unsupported strict schema, missing definition/tool provenance or malformed outputs block native suite confirmation, not ordinary OMP. Retain source observations and precise questions; never widen role tools, emulate removed tools, or repair malformed results into assurance. Read-only tool names are not a sandbox; prohibited attempted operations fail acceptance even if denied.

## Authorized assessment and recovery

An explicitly authorized file-loaded assessment uses a copied fifteen-skill source root and actor base-directory map. Resolve textual `skill://<name>/<relative-path>` pointers to those copied files with ordinary reads only. Do not silently select installed incumbents or implement a native resolver shim. Bind assessment identity from actual runtime records, not configuration intent. A transient caller-owned overlay may bind the existing role aliases only when the installed public interface supports it and the current authorization permits it. Never persist model/approval changes, copy credentials, install services, update OMP or auto-refresh upstream pins.

If current authenticated native execution cannot establish definition selection, record parsing/selection/behavior as unverified. Historical last-validated definitions are recovery material, not compatibility proof for the upgraded runtime. Do not deploy a known-invalid replacement or accept a same-named substitute. Later normal installer updates preserve collision-safe backups; this repository cutover has no live-home deployment. Recovery restores only changed managed payload from the pre-write copy and preserves unrelated files. Repeat these checks after each actual upgrade, with precise versions and exercised layers, not promises about all future releases.
