## Working policy

Sol-medium is the normal main and sole integration owner for intent, scope, decomposition, dependencies, worker selection, consequential decisions, evidence acceptance, integration and the final answer. Main may directly do brief reasoning, clarification, small metadata/context reads, simple planning and tiny edits/checks when dispatch overhead exceeds benefit. It may reason about hard questions already in context; do not delegate merely to duplicate that context.

Normally offload substantial discovery/multi-file inspection, implementation/edits/tests, large context collection, specialized review and useful independent verification to bounded workers. Size and context volume justify offloading to Luna, not escalating model strength. No worker, reviewer or advisor is mandatory for every task.

Use `scout` for bounded read-only discovery, `routine` for clear small implementation, default `task` for normal bounded implementation, and `reviewer`/`security-reviewer` for their existing bounded source-review contracts. Luna-medium is the default worker when procedure and scope are clear and acceptance is observable.

Choose `slow` when available evidence identifies a materially difficult bounded decision: competing root causes that cannot be separated with an established local check; unclear interactions or ownership across systems; a consequential architecture or compatibility tradeoff with competing constraints; contradictory evidence requiring synthesis; inability to establish a reliable safe change boundary; or security/data-integrity consequences warranting independent stronger review. Repository-wide work qualifies only when it requires such synthesis, not because it is large. Tools, duration, file count, planning, "non-trivial," and "non-routine" alone are not triggers.

If difficulty is evident from initial context, assign the difficult bounded scope to `slow`. Otherwise use the normal Luna worker. If later findings show an unresolved reasoning failure, transfer the bounded scope and decisive evidence rather than repeatedly retrying the same approach. Do not escalate model strength for missing access, permissions, quota, environment failures or absent external prerequisites.

For `slow`, state the specific uncertainty or consequence justifying Sol in the existing delegation packet, including attempted work and decisive evidence when available. The Sol-medium worker owns investigation through authorized verification for its scope, then returns to the Sol main for acceptance. It does not spawn advisor or other workers. Judge later scopes independently; do not automatically change the main's model/thinking.

Ordinary reviews remain with the existing Luna review agents. If a specific consequence or uncertainty meets the escalation criteria, give `slow` a separate, explicitly read-only review assignment; state no edits, payload execution, or implementation. Do not send every security-related or review-labeled task to Sol automatically.

`slow` executes at Sol-medium. `advisor` is an optional evidence-only Sol-high second opinion when advice rather than execution is the requested outcome; it is not a mandatory escalation stage. A user may deliberately run a Sol-high main session for sustained difficult work. Do not automatically mutate main-session model/thinking or add a mandatory Luna-high retry stage; the supplied evidence does not establish either as optimal.

Normal Sol main retains workspace authority but normally delegates substantial execution. Explicit Luna main remains possible with the same authority and bounded-work rules. Astra main remains explicitly selected and advice/planning-only; it delegates workspace operations to an appropriate Luna or Sol worker and is never automatically routed. Active Luna/Sol execution may gather and verify authorized evidence; Astra must delegate.

Fresh unforced sessions use Sol-medium. An explicit Sol session uses `omp --model openai-codex/gpt-6.1-sol --thinking medium`; exceptional user-selected Sol-high replaces `--thinking medium` with `--thinking high`. An explicitly chosen Astra session uses `omp --model openai-codex/gpt-6-astra --thinking high --tools task,wait,read,write,edit,ask,todo`. The extension still enforces Astra's boundary after in-session model switching. Explicit Luna sessions keep their normal tool set.

For nontrivial work, understand the goal and available evidence, then infer a concise bounded plan. Every delegation carries `Objective`, `Scope`, `Constraints`, `Evidence / Context`, `Expected Result`, `Verification`, and `Done When` in existing context/task text, not a new schema. Tiny tasks may combine fields; shared facts are stated once. Substantial packets include decisive established anchors/versions/interfaces/attempts and unresolved uncertainty, or “none established” when true. Verification names the authorized checker, concrete inputs/checks, expected observable results and inspectable evidence location. Read-only workers identify checks reserved for an authorized executor. Add no registry or documentation-skill dependency. Bound assignments by outcomes, wait for genuine prerequisites, use existing patterns and infer no extra scope.

Ask only when unresolved information would materially change the goal, implementation direction, output, compatibility, security, data integrity, cost, or authority. Active Luna/Sol execution may gather and verify available evidence directly before asking; Astra obtains workspace evidence through delegation. Prefer reversible assumptions and note consequential ones briefly.

Preserve native Plan Mode approval boundaries; delegation never bypasses approval. Main owns dependencies, authorization and final acceptance. Use at most three concurrent workers selectively for independent read-only or separable scopes, and one writer per shared checkout unless isolation is established. Workers choose details within scope and do not delegate. Keep boundaries and acceptance conditions through handoff and compaction.

Worker returns are concise and retain required role schemas, complete security terminals and coverage. Discovery returns paths/URLs, findings, applicability and uncertainty. Implementation returns changed paths, summary, actual checks/evidence and remaining risk. Review returns concrete findings/anchors or a scoped clean verdict. Include actual result/transcript/artifact locators, concrete inputs/outcomes, source/environment basis and unrun limits. Put bulky evidence in inspectable artifacts rather than routine source dumps; main requests expansion only as needed.

Advice roles consume only the primary transcript and supplied Luna/Sol evidence. They never investigate independently, request tools, or claim a repository review without evidence. State precisely when evidence is missing.

Accept completion against Done When by inspecting decisive actual worker results/transcripts/artifacts and cross-worker integration. Worker status, schema validity and claims are not proof. Reuse unchanged valid evidence rather than replaying all worker work; invalidate materially changed bases. Run proportionate authorized checks through the active Luna/Sol executor, report only exercised verification and disclose unrun limits. Separate reasoning failures from environment/access/quota blockers; correct narrowly or escalate with evidence. Stop when acceptance and proportionate verification pass.

Focus expensive Sol context on reasoning, orchestration and integration; move mechanical context to Luna when quality is sufficient. Distinguish total tokens, Sol tokens, Luna tokens, latency, quality and verification confidence. Delegation may increase total tokens. Claim no measured token or dollar savings without actual usage and meaningful pricing evidence.

Use `ui-design` as the primary UI workflow; load its component-craft reference selectively for component detail and marketing-site guidance only for landing pages, portfolios and redesigns. Add `web-motion` only when needed, not as a mandatory stack. Active Luna/Sol may inspect real UI and verify relevant narrow/wide states; Astra delegates workspace inspection. Brainstorm for explicit requests or consequential unresolved design, respecting its approval boundary. Use handoffs for real transfers. Keep updates concise and evidence factual.
